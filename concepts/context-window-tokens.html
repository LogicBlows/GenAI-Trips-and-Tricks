Context window, input & output tokens

30 Oct 2026 · Phase 0 · ~5 min read

EveryoneFundamentalsBuilders

Models read and write text as tokens — chunks of characters, not always whole words. The context window is the maximum tokens the model can consider in one request (input + output together, depending on provider).

From the deck

Input vs output tokens

TypeMeaningTypical billing
Input (prompt)System + history + user message + tool results you sendPer 1K / 1M input tokens
Output (completion)Text the model generatesOften priced separately; can cost more per token

Why context limits matter

$Cost

Long prompts and long answers scale cost roughly with token count.

⏱Latency

More input tokens → more work before the first output token appears.

✂Truncation

If conversation + docs exceed the window, oldest or middle content may be dropped — design summarization and retrieval.

Practical habits

  • Log prompt_tokens and completion_tokens from API responses in services.
  • Prefer attaching only relevant files or RAG chunks, not whole repos every turn.
  • See Prompt caching when the same long prefix repeats.

Rough sizes

Model reply ≈ 450 output tokens → bill ~5,570 tokens total for the call

Why "Hello world" ≠ 2 tokens

Tokenizers split oddly: " dependency" might be one token; IDs and code use more tokens per line.

Cursor habit

@ huge folder every message → input tokens spike → slower + costlier. Attach only what you need.

Token counts from the API beat rough “word × 1.3” estimates for budgeting.
